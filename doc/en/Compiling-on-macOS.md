# Compiling on macOS

The macOS port consists of the RHVoice engine compiled as a static library, an Audio Unit
app extension that provides the installed voices to the system (VoiceOver, Spoken Content and
every app that uses `AVSpeechSynthesizer`), and the RHVoice app that downloads and manages
voices. It requires macOS 13 Ventura or later, on Apple silicon or Intel Macs.

Everything lives in `src/macos`. The core sources (`src/core`, `src/hts_engine`) are used
unchanged.

## Requirements

* Xcode 15 or later (Xcode 26 is what the port is developed with).
* [XcodeGen](https://github.com/yonaskolb/XcodeGen), only when you change `project.yml`:
  `brew install xcodegen`.
* The repository with submodules: `git clone --recursive https://github.com/RHVoice/RHVoice.git`
  (only the Boost header modules under `external/libs/boost` are needed by the build; the
  language and voice submodules are used for the command-line smoke test).

## Building

```
cd src/macos
scripts/build.sh                 # Release build of the RHVoice app (regenerates the project if project.yml changed)
scripts/build.sh RHVoiceCLI      # rhvoice-cli, the upstream RHVoice-test tool
CONFIGURATION=Debug scripts/build.sh
```

Or open `src/macos/RHVoice.xcodeproj` in Xcode and build the `RHVoice` scheme. Products end
up in `src/macos/build/DerivedData/Build/Products/<configuration>/`.

To synthesize from the command line with the voices checked out in `data/`:

```
export RHVOICE_DATA_PATH=$PWD/data RHVOICE_CONFIG_PATH=$PWD/config
echo "Hello from macOS." | src/macos/build/DerivedData/Build/Products/Release/rhvoice-cli -p alan -q max -o hello.wav
afplay hello.wav
```

The engine is compiled as C++14 and without `HTS_EMBEDDED`, so the voices sound exactly as
they do on Windows and Linux. See `src/macos/Config/Core.xcconfig` for the exact flags.

If a SCons or CMake build has generated `src/core/config.h` or `src/include/core/config.h`,
remove them first: the macOS build supplies its own `config.h` and the generated ones would
shadow it (`scripts/build.sh` checks for this).

## Signing and the app group

The app and the extension share voice data through an app group. Copy
`src/macos/Config/Local.xcconfig.template` to `Local.xcconfig` (ignored by git) and set your
team:

```
DEVELOPMENT_TEAM = ABCDE12345
CODE_SIGN_IDENTITY = Apple Development
APP_GROUP_ID = $(TeamIdentifierPrefix)org.rhvoice.RHVoice
```

Without a team the project falls back to ad-hoc signing and the unprefixed group
`org.rhvoice.RHVoice`; macOS 15 and later then ask for confirmation the first time the app
accesses the shared container. Voice data is stored in
`~/Library/Group Containers/<group>/Library/Application Support/RHVoice/`.

## Registering the synthesizer with the system

Launch the app once. macOS registers the embedded extension and the app tells the speech
system that voices are available (`AVSpeechSynthesisProviderVoice.updateSpeechVoices()`).
The system can take up to 30 seconds to refresh its voice list. Installed voices then appear
in VoiceOver Utility under Speech, in the VoiceOver Speech rotor, and in
System Settings > Accessibility > Spoken Content.

Useful checks:

```
pluginkit -m -p com.apple.AudioUnit -v | grep -i rhvoice     # is the extension registered?
auval -v ausp rhvc RHVo                                       # does the audio unit load?
swift src/macos/scripts/list-voices.swift                     # which voices does the system list?
swift src/macos/scripts/speak.swift <identifier> "Hello"      # speak through the system synthesizer
/usr/bin/log stream --info --predicate 'subsystem == "org.rhvoice.RHVoice"'
```

If several builds of the app exist on the disk, PlugInKit may pick an old copy. Keep one
copy, or unregister stale ones with `pluginkit -r <path to RHVoiceSynthesizer.appex>`.

## Tests

```
cd src/macos
xcodebuild -project RHVoice.xcodeproj -scheme RHVoice -configuration Debug -derivedDataPath build/DerivedData test
```

The unit tests cover the package index, dependency rules, archive extraction (including the
path-traversal guard), locale mapping, SSML normalization, and audio queue continuity,
timeouts and cancellation. Two integration tests download
a small voice and two demo clips from the live server and are skipped when it is unreachable.

## Distribution

The app cannot be sold through the Mac App Store (the engine is LGPL and several voices are
non-commercial), so it is distributed as a notarized disk image:

```
cd src/macos
scripts/notarize.sh    # needs Developer ID certificates and a notarytool keychain profile named "RHVoice"
```

## Generated files

* `RHVoice.xcodeproj` is generated from `project.yml` with XcodeGen; edit the YAML, not the project.
* `RHVoice/Resources/voice-metadata.json` (creators and licenses shown in the app) is generated by
  `scripts/generate-voice-metadata.py` from the voice repositories and
  `scripts/voice-metadata.overrides.json`.
* `RHVoice/Resources/Localizable.xcstrings` is generated by `scripts/import-android-strings.py`
  from the Android app's translations.

The CI job checks that all three are up to date.
